# OKRI 성과 측정

데이터 탭에서 KR의 **KR 데이터 설정 → 성과 측정 설정**을 엽니다. 측정 규칙은 적용 시작일로 구분합니다. 규칙을 바꾼 시각, 변경한 사용자, 적용 시작일, 사유와 전후 값은 **변경 이력**에서 조회합니다.

## KR 측정 규칙

| 데이터 형태 | 가능한 집계 | 예시 |
| --- | --- | --- |
| 날짜가 있는 발생량 | 합계 | 절감 시간, 완료한 배송 건수 |
| 시점별 측정값 | 마지막 값 또는 평균 | 잔액, 주간 유입량 이동평균, 응답 시간 |
| 계속 증가하는 누적계 | 변화량 합계 | 최초 수집 이후 증가한 전체 주문 건수 |

평가 기간은 월간, 주간(월요일 시작), 지정 기간, 전체 기간 중에서 고릅니다. 월간 합계는 KR 시간대의 해당 월만 집계합니다. 기준값은 목표 달성률을 계산하는 비교점입니다. 예를 들어 이벤트 합계가 8시간이면 기준값과 관계없이 기간 실적은 8시간입니다. 증가·감소 방향에 맞는 목표값을 설정합니다.

API 측정의 성과 날짜는 수집 시각을 KR 시간대로 변환한 날짜입니다. 집계에 쓰는 월이 원천 시스템의 월과 다르면 원천 날짜로 **직접 입력**을 사용합니다. 시점별 평균은 보관된 관측값의 산술평균입니다. 누적계는 직전 값과 비교한 차이만 기록하며 첫 관측과 리셋 직후 변화량은 별도 표시합니다. 직접 입력은 동일한 성과 기록 ID로 정정할 수 있습니다.

## Project 기여

Project 성과 합산 KR은 일회성, 매일, 영업일마다, 매주 기여를 지원합니다. 매주는 운영 시작일의 요일을 따릅니다. 반복 기여는 완료된 현지 날짜부터, 일회성은 지정일에 반영합니다. 운영 종료일과 중지 기간의 양 끝 날짜가 포함되며 중지 종료일을 비우면 계속 중지합니다. 운영 여부는 구축 완료와 별도로 토글합니다. Project 또는 상위 연결이 이동·보관되면 운영 기여가 정지되고 이미 적립된 날짜는 원래 KR에 남습니다. 같은 KR에서 재개하려면 운영 규칙을 다시 저장합니다.

**산정 근거**에 계산 방식이나 실측 출처를 남깁니다. 추정과 실측을 함께 볼 수 있고 그래프에서 추정치를 제외할 수 있습니다. Project 실적 기록은 같은 Project·날짜의 정기 산정값을 대체합니다. 날짜별 기록에 대한 정정이나 과거 날짜로의 규칙 적용에는 사유를 남깁니다. 반복 기여에 쓰는 달력은 규칙 저장 시 버전으로 고정합니다. 이후 휴일을 바꾸려면 새 적용 시작일로 Project 규칙을 저장합니다.

기존 KR은 새 규칙을 저장하는 시점에 전환됩니다. 기존 날짜 기반 일정과 날짜는 첫 Project 규칙에 재사용됩니다. 과거 일정까지 포함하려면 해당 날짜를 포함하는 적용 시작일을 지정합니다. 기존 완료 성과와 API 수집 이력은 유지됩니다. 날짜별 원천이 없는 완료 누적값을 새 평가 기간에 옮기려면 근거가 있는 날짜별 기록을 등록합니다.

## 그래프와 MCP

기존 OKR의 KR을 펼치면 일·주·월과 조회 기간, 기간 실적·구간 합계·누적 추이, 목표, 추정 포함 여부 및 기준일을 볼 수 있습니다. 마지막 값과 평균은 해당 방식의 기간 추이를 표시합니다. 기간 요약은 마지막 날짜에 적용되는 측정 규칙의 단위와 원천을 기준으로 하며 다른 원천과 단위의 이력은 그래프에서 별도로 이어집니다. Project 합계와 원본 날짜별 기록은 같은 집계 결과에서 가져옵니다.

1. `get_kr_measurement_rule` 및 `get_project_contribution_rule`에서 설정과 현재 리비전을 읽습니다.
2. `set_kr_measurement_rule`, `set_project_contribution_rule` 및 `record_kr_performance`에 `effective_date`, `expected_revision`, `request_id`를 전달합니다. 응답에는 변경 전후 값, 영향 기간 및 현재 평가 결과가 포함됩니다. 같은 수정 요청을 재시도할 때는 동일한 ID와 입력을 전달합니다.
3. `get_kr_performance`에는 `start`, `end`, `grain`, `include_estimates`를 지정할 수 있습니다. `project_id`는 날짜별 상세를 좁힙니다. `list_kr_performance_changes`의 리비전으로 별도 변경 이력을 페이지 단위로 읽습니다.
4. 기존 Project 측정·기여 일정·달력 도구는 기존 방식의 KR을 지원합니다. 새 규칙을 사용하는 KR의 편집에는 버전 기반 도구를 사용합니다. 작업공간 달력은 `get_metric_calendar`와 관리자용 `set_metric_calendar`로 관리합니다.

## 적용 사례 · AX 절감시간

- KR을 **시간 / 월간 / 합계 / 증가 / Project 성과 합산**으로 설정합니다. 기준값이 0시간이면 목표값은 팀이 합의한 월간 절감 시간입니다.
- 각 Project에 운영 일정, 회당 절감 시간, 운영 시작일, 산정 근거, 추정 여부를 저장합니다. 업무일에 한 건씩 처리하는 자동화는 **영업일마다**, 날마다 처리하는 자동화는 **매일**, 단발성 절감은 **1회성**으로 지정합니다.
- 일별 추정값을 대체할 실측이 들어오면 같은 Project와 실적 날짜로 기록합니다. 월간 평가값은 월이 바뀔 때 새로 시작하고 지난 달 기록과 운영 기간 누적 추이는 계속 조회할 수 있습니다.
